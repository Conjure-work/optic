# Testing Optic

Two layers, one command each, both run by `.github/workflows/tests.yml` on every pull request and every push to
`main`. The count each run made is in the run's summary.

| Layer | Where | What it covers |
| --- | --- | --- |
| Python suite | `tests/*.py` | Routes through FastAPI's TestClient, the analytics, and the front end's modules run in JavaScriptCore or read as text (the project's pattern for client contracts, see CLAUDE.md) |
| Browser journeys | `tests/e2e/` | The real server in a subprocess and a real Chromium: Home and the stock page at each level, Show more, the level kept across reloads and devices, the Milo prompts and sign-in from them, Anthropic down, the first usage signal, the accessibility scan (WCAG 2.1 A and AA) and the keyboard |

## Running them from a fresh clone

Everything a run needs, and nowhere else:

- Python 3.12, and `python -m pip install -r requirements-dev.txt` (the app's own requirements plus the test tools)
- Chromium for Playwright: `python -m playwright install chromium`
- A JavaScriptCore shell for the full count: about a thousand tests run v2's modules in it. macOS has one in the
  JavaScriptCore framework; on Ubuntu or Debian, `apt-get install libjavascriptcoregtk-bin` gives `/usr/bin/jsc`
  (CI runs on Ubuntu since 2026-11-24). `tests/support/jsc.py` finds it (the `JSC` environment variable overrides);
  `python -m tests.support.jsc` prints what it found. Without one those tests skip, and CI fails on any skip but
  `tests/test_brokerage_exposure.py::test_live_qqq`
- `git` on the path (one test asks git what `.gitignore` covers)
- No network: pin outbound HTTP to a closed port so nothing can reach a real provider

```bash
export HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9 NO_PROXY=127.0.0.1,localhost
python -m pytest -q                 # both layers
python -m pytest -q tests/e2e       # the browser journeys alone
```

The journeys start the app with `uvicorn` on a free local port and a fresh data directory. Anthropic is played by
`tests/support/anthropic_stub.py`, a recording stub on its own local port (`ANTHROPIC_BASE_URL`), which can answer,
time out or fail; every other provider host is refused at the closed port. The few symbol and quote answers the
stock page needs come from `tests/e2e/fixtures.py`, invented values labelled as such.

### Public routes, by reason

- **The app's pages and static files: the shell every reader loads, with no account data in it (v2 or the classic page by the owner's switch)** (5): `* /`, `GET /`, `GET /classic`, `GET /v2/`, `GET /v2/index.html`
- **FastAPI's schema and docs pages: they describe the routes and carry no data** (4): `GET /docs`, `GET /docs/oauth2-redirect`, `GET /openapi.json`, `GET /redoc`
- **Health and build checks for the platform and the deploy; the operator's detail is added only for the owner's session** (3): `GET /api/build`, `GET /api/health`, `GET /healthz`
- **Signing in, signing up and recovering an account: they must work without a session; rate-limited per address and per client (app/auth/ratelimit.py); `me` and `logout` answer a guest as signed out** (14): `GET /api/auth/apple/callback`, `POST /api/auth/apple/callback`, `POST /api/auth/forgot-password`, `GET /api/auth/google/callback`, `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/me`, `POST /api/auth/passkeys/login/options`, `POST /api/auth/passkeys/login/verify`, `GET /api/auth/providers`, `POST /api/auth/register`, `POST /api/auth/reset-password`, `GET /api/auth/reset/check`, `POST /api/auth/verify-email`

**The denial test for every guarded route.** The inventory above reads the guards from the code; `tests/test_audit_guard_denials.py` sends a request each guarded route must refuse (signed out, and as a signed-in reader who is not the owner for the owner routes) and checks the code: 401 for the session and write guards, 403 for a reader on an owner route, 400 for an unsigned Stripe delivery, 401 for an unsigned brokerage one. The sweep is `tests/support/guard_denials.py`; five routes use a guard as a question rather than a refusal and are listed there under `PREDICATE`, and two need a request shaped to reach their guard (`OVERRIDES`). Against a running copy: `python -m tests.support.guard_denials --base <url> [--reader-cookie-file <path>]` (the file holds a reader's Cookie header; it sends only requests that must be refused and exits 1 on any miss).

## Adding a test

A route: beside `tests/test_pass1_usage.py`, with the `accounts` fixture for a fresh database. A journey: in
`tests/e2e/`, opening its own browser context with `open_page` and its own account with `make_account`, so a rerun
never depends on what ran before.

## What no test drives

- Google, Apple and passkey sign-in: they need the providers' own pages and a real authenticator.
- Real market data: every feed is refused at the closed port, so panels that need one show their outage state.
- The live owner account on theopticterminal.com: the owner guard is tested with accounts the tests make.
